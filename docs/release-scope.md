# 开源整理范围

本仓库从 muse2api 的 Go 实现单独提取，仅发布协议方法与可运行示例，使用新的 Git 历史。

## 纳入

- 密码登录与调用方提供验证码的登录。
- 会话校验、Cookie 轮换、VM 唤醒和临时令牌引导。
- WebSocket、Noise XX、protobuf 编解码与多路 RPC。
- 对话流、历史轮询、审批处理、图片 / 视频识别及下载。
- HTTP(S) / SOCKS 代理、模拟服务测试和 CI。

## 排除

- 账号和密码来源、账号注册、收件箱和接码平台实现。
- 原项目 `.env`、账号数据、Cookie、令牌、代理凭据、媒体、日志、部署文件和 Git 历史。
- 浏览器 / CDP 驱动、管理后台、账号池调度、任务持久化及 API 兼容服务。

示例使用保留用途的 `example.com`、`.test` 和本地模拟地址。公开协议服务地址属于协议本身，没有替换成无法运行的占位符；Noise 测试中的固定私钥属于公开测试向量，不是生产凭据。

## 凭据处理

密码、验证码只参与本次登录，库不主动保存；示例从调用方环境变量或终端获取，成功后 Cookie 仅保留在当前进程。`login.Result`、`muse.Account`、`hatch.Session` 的凭据字段不参与 JSON 序列化。

Cookie 轮换通过 hook 交给使用者；如需长期运行，由使用者实现存储、访问控制和账号快照同步。生成媒体会写入配置目录。默认日志静默；公开错误与诊断不回显上游正文或认证令牌。

## 实际限制

- 依赖已有 Muse 账号以及其支持的登录方式；遇到额外验证会停止。
- `GetOTP` 是同步回调，调用方须响应传入 context，否则会阻塞该次调用。
- 密码初始化可能触发上游发码，但密码流程不取码、不确认验证码。
- 不支持需要 RV 密钥认证的机密 VM，也不提供硬件远程证明验证。
- `Chat` 每次使用新会话；多轮上下文和账号调度由调用方管理。
- 媒体张数、尺寸和时长由上游实际输出决定，`N` 只限制最多返回数量。
- 本次整理的验证使用合成凭据与本地模拟网关，没有使用原项目真实凭据进行联网登录或生成。
